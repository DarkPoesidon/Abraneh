# راهنمای نصب و راه‌اندازی WIHM-Cloudflare از صفر

> **روش ساده‌تر:** [نصب‌کنندهٔ خودکار و راهنمای کوتاه](EASY-INSTALL.fa.md) برای ویندوز، مک، لینوکس و اندروید با ترموکس آماده است. دیتابیس، کلید امنیتی و انتشار را خودش انجام می‌دهد؛ نیازی به ویرایش فایل نیست. متن زیر روش دستی را توضیح می‌دهد.

با انجام مراحل این راهنما، یک آدرس اینترنتی برای پیام‌رسان خود می‌گیرید. کاربران آن آدرس را باز می‌کنند، حساب می‌سازند و پیام می‌فرستند. بعد از انتشار، برنامه روی Cloudflare اجرا می‌شود و برای کارکردن آن لازم نیست رایانهٔ شما روشن بماند.

اگر فقط می‌خواهید از پیام‌رسانی که شخص دیگری راه‌اندازی کرده استفاده کنید، آدرس آن را بگیرید و از [ساخت حساب و ارسال پیام](#use) شروع کنید. نصب ابزارهای برنامه‌نویسی و ساخت حساب Cloudflare مربوط به کسی است که پیام‌رسان را راه‌اندازی می‌کند.

این راهنما برای Windows 11، macOS و Ubuntu نوشته شده است. بخش مخصوص سیستم‌عامل خود را انجام دهید؛ مراحل مشترک برای همه یکسان‌اند.

تاریخ بررسی راهنما: ۲۸ اکتبر ۲۰۲۶. عنوان بعضی دکمه‌های سایت‌ها ممکن است با زبان یا نسخهٔ رابط کاربری فرق کند.

## ۱. پیش از شروع

برای راه‌اندازی به این موارد نیاز دارید:

- یک رایانه با اینترنت و اجازهٔ نصب نرم‌افزار؛
- مرورگری مانند Chrome، Edge، Firefox یا Safari؛
- یک ایمیل برای ساخت حساب Cloudflare؛
- ابزارهای Node.js و Git که نصب آن‌ها در مرحلهٔ ۳ توضیح داده شده است.

نسخهٔ فعلی ابزار Cloudflare به‌صورت رسمی از Windows 11، macOS 13.5 به بالا و لینوکس دارای glibc 2.35 به بالا پشتیبانی می‌کند. برای مسیر لینوکس این راهنما از Ubuntu 22.04 یا جدیدتر استفاده کنید. Windows 10 جزو سیستم‌های پشتیبانی‌شدهٔ اجرای مستقیم Wrangler نیست. [شرایط رسمی اجرای Wrangler](https://developers.cloudflare.com/workers/wrangler/install-and-update/)

برای شروع به VPS، Docker، خرید دامنه یا حساب GitHub نیاز ندارید. فایل‌های این ریپو عمومی‌اند و بدون ورود به GitHub قابل دریافت هستند. خود برنامه را روی Cloudflare Workers منتشر می‌کنید؛ فعال‌کردن GitHub Pages یا آپلود پوشهٔ `public` به‌تنهایی، بخش سرور و پیام‌رسان را راه‌اندازی نمی‌کند.

می‌توانید با سهمیهٔ Workers Free شروع کنید؛ Durable Objects با ذخیره‌سازی SQLite، مانند همین پروژه، روی پلن Free در دسترس است. سهمیه‌ها محدودند و با عبور از آن‌ها ممکن است درخواست‌ها خطا بدهند. مصرف بالاتر روی پلن پولی هزینه دارد. پیش از انتخاب پلن پولی، [محدودیت‌ها و هزینهٔ Workers](https://developers.cloudflare.com/workers/platform/pricing/)، [Durable Objects](https://developers.cloudflare.com/durable-objects/platform/pricing/) و [D1](https://developers.cloudflare.com/d1/platform/pricing/) را ببینید. هر صفحهٔ باز برنامه، فهرست گفتگوها را هر ۵ ثانیه تازه می‌کند؛ تعداد کاربران باز هم بر مصرف اثر دارد.

چند ویژگی نسخهٔ فعلی را پیش از انتشار بدانید:

- ثبت‌نام برای هر کسی که به آدرس برنامه دسترسی دارد باز است. پنل مدیریت و تأیید عضویت توسط مدیر وجود ندارد.
- پیام‌ها متنی هستند. ارسال فایل، تماس صوتی و تصویری و اعلان Push در پس‌زمینه پیاده‌سازی نشده‌اند.
- بازیابی رمز عبور با ایمیل وجود ندارد؛ رمز حساب خود را در جای امن نگه دارید.
- پیام‌ها رمزگذاری سرتاسری ندارند. صاحب حساب میزبانی می‌تواند به داده‌های ذخیره‌شده دسترسی داشته باشد.
- بازکردن ظاهر کش‌شدهٔ برنامه بدون اینترنت، به معنی امکان ارسال یا دریافت آفلاین پیام نیست.

چهار نامی که در ادامه می‌بینید:

| نام | معنی و محل استفاده |
| --- | --- |
| `WIHM-Cloudflare` | نام ریپو و پوشهٔ دریافت‌شده از GitHub |
| `cloudflare-messenger` | نام پیش‌فرض برنامه در حساب Cloudflare؛ در خط `name` فایل `wrangler.toml` قرار دارد |
| `messenger-db` | نام دیتابیس؛ دستورهای آمادهٔ این پروژه از همین نام استفاده می‌کنند |
| `JWT_SECRET` | کلید محرمانهٔ سرور برای اعتبارسنجی ورود کاربران؛ با رمز حساب کاربری فرق دارد |

## ۲. چطور دستورها را اجرا کنیم؟

«ترمینال» پنجره‌ای است که دستور را در آن می‌نویسید و Enter می‌زنید.

### در ویندوز

1. دکمه‌های `Win + R` را بزنید.
2. بنویسید `cmd` و Enter بزنید.
3. پنجرهٔ Command Prompt باز می‌شود. در این راهنما دستورهای ویندوز را در همین پنجره اجرا کنید.

اگر از Windows Terminal استفاده می‌کنید، از فلش کنار زبانه‌ها، `Command Prompt` را انتخاب کنید. مسیرهای نمونهٔ ویندوز در این راهنما برای `cmd` نوشته شده‌اند.

### در مک

`Command + Space` را بزنید، `Terminal` را جستجو و باز کنید.

### در Ubuntu

`Ctrl + Alt + T` را بزنید تا Terminal باز شود.

### روش خواندن دستورها

- فقط متن داخل کادر دستور را کپی کنید؛ علامت‌های دور کادر و عنوان‌هایی مانند `bash` را ننویسید.
- اگر کادر چند خط دارد، هر خط را جداگانه اجرا کنید و صبر کنید تمام شود.
- تا وقتی نتیجهٔ مرحلهٔ فعلی را ندیده‌اید، دستور بعدی را اجرا نکنید.
- دستور را با صفحه‌کلید انگلیسی و همان علامت‌های نقل‌قول داخل نمونه کپی کنید.
- نوشته‌هایی که زیر عنوان «نمونهٔ خروجی» هستند دستور نیستند.
- معمولاً با برگشتن نام پوشه و نشانگر تایپ، اجرای دستور تمام شده است. دستور `npm run dev` استثناست و تا زمانی که آن را متوقف نکنید باز می‌ماند.

اگر پنجره را بستید، برای ادامه باید دوباره وارد پوشهٔ پروژه شوید؛ روش آن در مرحلهٔ ۴ آمده است.

## ۳. نصب Node.js و Git

Node.js ابزار اجرای برنامه‌های لازم برای آماده‌کردن پروژه است. ابزارهای `npm` و `npx` همراه آن نصب می‌شوند. Git فایل‌های پروژه را دریافت می‌کند و بعداً برای دریافت تغییرات به کار می‌رود.

این پروژه با Node.js 24 آزمایش شده است. نسخهٔ 24 در زمان بررسی این راهنما LTS است. از آخرین به‌روزرسانی شاخهٔ 24 استفاده کنید. [دریافت Node.js](https://nodejs.org/en/download)، [وضعیت نسخه‌ها](https://nodejs.org/en/about/previous-releases)

### Windows 11

1. [صفحهٔ دریافت Node.js](https://nodejs.org/en/download) را باز کنید.
2. نسخهٔ `24 LTS`، سیستم `Windows` و بستهٔ نصب `Windows Installer (.msi)` را انتخاب کنید.
3. معماری معمول رایانه‌های Intel و AMD، `x64` است. اگر در `Settings > System > About` نوع پردازنده ARM نوشته شده است، `ARM64` را انتخاب کنید.
4. فایل نصب را اجرا کنید؛ توافق‌نامه را بپذیرید و تنظیمات پیش‌فرض نصب را نگه دارید. نصب `npm` و افزودن ابزارها به `PATH` باید فعال بماند.
5. اگر گزینهٔ نصب خودکار ابزارهای اضافی ساخت برنامه نمایش داده شد، برای مراحل معمول این پروژه لازم نیست آن را فعال کنید.
6. از [صفحهٔ رسمی Git for Windows](https://git-scm.com/install/windows)، بستهٔ Setup مناسب معماری رایانه را دریافت و نصب کنید. تنظیمات پیش‌فرض کافی است؛ دسترسی Git از خط فرمان را غیرفعال نکنید.
7. تمام پنجره‌های Command Prompt قبلی را ببندید و یک پنجرهٔ جدید باز کنید.
8. این سه دستور را یکی‌یکی اجرا کنید:

```bat
node --version
npm --version
git --version
```

باید برای هر سه، شمارهٔ نسخه ببینید. خروجی Node باید با `v24.` شروع شود؛ شمارهٔ دقیق به‌روزرسانی می‌تواند متفاوت باشد. اگر پیام `not recognized` گرفتید، بخش رفع خطا را ببینید.

### macOS

1. از [صفحهٔ دریافت Node.js](https://nodejs.org/en/download)، نسخهٔ 24 LTS و بستهٔ نصب macOS با پسوند `.pkg` را بگیرید.
2. بسته را اجرا و نصب را کامل کنید. برای مک‌های Apple Silicon معماری `ARM64` و برای مک‌های Intel معماری `x64` مناسب است، اگر صفحه بین این دو انتخاب خواست.
3. Terminal را باز کنید و اجرا کنید:

```bash
git --version
```

4. اگر سیستم پیشنهاد نصب Command Line Tools را داد، آن را نصب کنید و صبر کنید تمام شود. اگر Git موجود نبود و پیشنهادی ندیدید، اجرا کنید:

```bash
xcode-select --install
```

5. Terminal را ببندید و دوباره باز کنید؛ سپس هر سه ابزار را بررسی کنید:

```bash
node --version
npm --version
git --version
```

### Ubuntu 22.04 یا جدیدتر

ابتدا Git و ابزار دریافت فایل را نصب کنید:

```bash
sudo apt update
sudo apt install -y git curl ca-certificates
```

اگر رمز رایانه خواسته شد، آن را بنویسید و Enter بزنید؛ هنگام نوشتن ممکن است هیچ کاراکتری نشان داده نشود.

برای نصب Node.js 24 از `nvm` استفاده کنید. دستور زیر اسکریپت نصب را از مخزن رسمی نگه‌دارندهٔ nvm دریافت و اجرا می‌کند. [راهنمای رسمی nvm](https://github.com/nvm-sh/nvm#installing-and-updating)

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.8/install.sh | bash
```

Terminal را ببندید و دوباره باز کنید؛ سپس:

```bash
command -v nvm
nvm install 24
nvm alias default 24
node --version
npm --version
git --version
```

دستور اول باید `nvm` و دستورهای آخر شمارهٔ نسخه نشان دهند. اگر `nvm` پیدا نشد، برای ترمینال پیش‌فرض Bash اجرا کنید و دوباره امتحان کنید:

```bash
source ~/.bashrc
```

## ۴. دریافت فایل‌های پروژه

یکی از دو روش زیر را انتخاب کنید. روش Git برای دریافت به‌روزرسانی‌ها مناسب‌تر است.

### روش اول: دریافت با Git

در Windows، این دستورها را در Command Prompt اجرا کنید:

```bat
cd /d "%USERPROFILE%"
git clone https://github.com/DarkPoesidon/WIHM-Cloudflare.git
cd WIHM-Cloudflare
```

در macOS یا Ubuntu:

```bash
cd ~
git clone https://github.com/DarkPoesidon/WIHM-Cloudflare.git
cd WIHM-Cloudflare
```

Git برای دریافت این ریپوی عمومی نباید رمز حساب GitHub بخواهد. اگر گفت پوشهٔ `WIHM-Cloudflare` از قبل وجود دارد، دوباره روی همان پوشه clone نکنید؛ اگر قبلاً پروژه را دریافت کرده‌اید، فقط وارد همان پوشه شوید.

برای دیدن فایل‌ها در Windows دستور `dir` و در مک یا لینوکس دستور `ls` را اجرا کنید. باید فایل‌های `package.json`، `wrangler.toml` و `schema.sql` و پوشه‌های `src` و `public` را ببینید. از این مرحله به بعد، همهٔ دستورهای پروژه را در همین پوشه اجرا کنید.

اگر بعداً پنجره را بستید، برای برگشت به این مسیر در Windows:

```bat
cd /d "%USERPROFILE%\WIHM-Cloudflare"
```

در مک یا لینوکس:

```bash
cd ~/WIHM-Cloudflare
```

### روش دوم: دریافت ZIP

1. [صفحهٔ پروژه](https://github.com/DarkPoesidon/WIHM-Cloudflare) را باز کنید.
2. دکمهٔ `Code` و سپس `Download ZIP` را بزنید.
3. فایل ZIP را کامل استخراج کنید. در ویندوز روی فایل راست‌کلیک و `Extract All` را انتخاب کنید.
4. وارد پوشهٔ استخراج‌شده شوید؛ نام معمول آن `WIHM-Cloudflare-main` است. همان پوشه‌ای را پیدا کنید که فایل `package.json` داخل آن قرار دارد.
5. در Windows، داخل همان پوشه روی نوار آدرس File Explorer کلیک کنید، `cmd` بنویسید و Enter بزنید. Command Prompt در همان مسیر باز می‌شود.
6. در مک یا لینوکس، در Terminal بنویسید `cd `، پوشهٔ استخراج‌شده را از فایل‌منیجر به پنجره بکشید و Enter بزنید.

فایل‌ها را از داخل پنجرهٔ ZIP اجرا نکنید. در روش ZIP، دستورهای `git pull` این راهنما قابل استفاده نیستند.

## ۵. نصب بسته‌های پروژه و بررسی اولیه

داخل پوشهٔ پروژه اجرا کنید:

```bash
npm ci
```

این دستور نسخه‌های مشخص‌شده در `package-lock.json` را نصب می‌کند. تا تمام‌شدن دریافت فایل‌ها صبر کنید. پوشهٔ `node_modules` خودکار ساخته می‌شود؛ لازم نیست آن را دانلود یا جابه‌جا کنید. بار اول به اینترنت دسترسی‌پذیر به سرویس‌های npm و GitHub نیاز دارید.

سپس:

```bash
npx wrangler --version
```

باید نسخهٔ Wrangler نصب‌شده در پروژه را ببینید. Wrangler ابزار ارتباط با Cloudflare است و با `npm ci` نصب شده؛ نصب سراسری جداگانه لازم نیست.

برای بررسی فایل‌ها و تست‌های برنامه:

```bash
npm run typecheck
npm test
```

در دستور اول نباید خطای TypeScript ببینید. در دستور دوم، نسخهٔ همراه این راهنما ۱۴ تست دارد و باید تعداد خطاها صفر باشد. تست‌ها دیتابیس موقت می‌سازند و اطلاعات محیط اصلی شما را تغییر نمی‌دهند. اگر خطا دارید، پیش از انتشار سراغ [رفع خطا](#troubleshooting) بروید.

وجود عبارت‌هایی مانند `npm notice` به‌تنهایی به معنی شکست نصب نیست. در بعضی نسخه‌های npm، هشدار `allow-scripts` هم نمایش داده می‌شود؛ اگر بررسی‌ها و اجرای برنامه موفق‌اند، این هشدار به‌تنهایی مانع ادامه نیست. اگر npm هشدار آسیب‌پذیری داد، آن را جدا بررسی کنید؛ برای عبور از نصب، کورکورانه `npm audit fix --force` اجرا نکنید، چون نسخه‌های وابستگی را تغییر می‌دهد.

## ۶. ساخت حساب Cloudflare و ورود

1. [داشبورد Cloudflare](https://dash.cloudflare.com/) را باز کنید.
2. اگر حساب ندارید، `Sign up` را انتخاب و با ایمیل خود حساب بسازید.
3. اگر ایمیل تأیید دریافت کردید، آن را تأیید کنید.
4. وارد حساب شوید. برای این مسیر لازم نیست دامنه اضافه کنید؛ آدرس `workers.dev` را در مرحلهٔ انتشار می‌گیرید.
5. به ترمینال داخل پوشهٔ پروژه برگردید و اجرا کنید:

```bash
npx wrangler login
```

مرورگر صفحهٔ مجوز Cloudflare را باز می‌کند. بررسی کنید داخل حساب خودتان هستید و درخواست Wrangler را با `Allow` تأیید کنید. ترمینال را تا دریافت پیام ورود موفق باز نگه دارید.

سپس بررسی کنید:

```bash
npx wrangler whoami
```

باید حساب و Account ID خود را ببینید. اگر چند حساب در خروجی وجود دارد، حسابی را انتخاب کنید که می‌خواهید برنامه و دیتابیس در آن ساخته شوند. برای تعیین صریح آن، تنظیم `account_id` در مرحلهٔ بعد توضیح داده شده است.

اگر مرورگر خودکار باز نشد، لینک چاپ‌شده در ترمینال را باز کنید. اگر ورود روی آدرس `localhost` گیر کرد، روش بدون برگشت محلی را اجرا کنید:

```bash
npx wrangler login --device
```

در این روش یک لینک و کد کوتاه نمایش داده می‌شود. لینک را باز کنید، کد را وارد و درخواست را تأیید کنید؛ بعد منتظر پیام موفقیت ترمینال بمانید. اگر کد منقضی شد، همان دستور را دوباره اجرا کنید. [مستندات ورود و بررسی حساب](https://developers.cloudflare.com/workers/wrangler/commands/general/)

<a id="database"></a>
## ۷. ساخت دیتابیس و تنظیم فایل پروژه

دیتابیس محل نگهداری کاربران و اطلاعات گفتگوهاست. این مرحله دیتابیس آنلاین را در حساب Cloudflare شما می‌سازد:

```bash
npx wrangler d1 create messenger-db --update-config=false
```

اگر انتخاب حساب خواسته شد، همان حساب مرحلهٔ قبل را انتخاب کنید. گزینهٔ `--update-config=false` باعث می‌شود تنظیم فایل را در قدم بعد خودتان انجام دهید.

در خروجی، بخش مربوط به دیتابیس و یک شناسه شبیه این می‌بینید. این فقط نمونهٔ خروجی است؛ شناسهٔ واقعی شما متفاوت خواهد بود:

```toml
[[d1_databases]]
binding = "DB"
database_name = "messenger-db"
database_id = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
```

رشتهٔ واقعی مقابل `database_id` را کپی کنید. [راهنمای رسمی ساخت D1](https://developers.cloudflare.com/d1/get-started/)

### ویرایش `wrangler.toml`

1. فایل `wrangler.toml` را در پوشهٔ پروژه پیدا کنید.
2. در ویندوز، روی آن راست‌کلیک و `Open with > Notepad` را انتخاب کنید. در مک یا لینوکس از ویرایشگر متن ساده استفاده کنید؛ Word برای این فایل مناسب نیست.
3. نزدیک انتهای فایل، این خط را پیدا کنید:

```toml
database_id = "local-messenger-db"
```

4. فقط متن بین دو علامت `"` را با شناسهٔ واقعی دیتابیس جایگزین کنید. خود علامت‌های نقل‌قول را نگه دارید.
5. فایل را با همان نام و پسوند `wrangler.toml` ذخیره کنید؛ نام نباید به `wrangler.toml.txt` تبدیل شود.

بقیهٔ فایل برای نصب عادی همین پروژه آماده است. بخش `[[d1_databases]]` دیگری اضافه نکنید و نام‌های `DB` و `CHAT_ROOM` را عوض نکنید.

اگر فقط یک حساب Cloudflare دارید، معمولاً تعیین Account ID لازم نیست. اگر چند حساب دارید، شناسهٔ حساب درست از خروجی `whoami` را در یک خط جدید، بلافاصله پس از خط اول `name` اضافه کنید:

```toml
name = "cloudflare-messenger"
account_id = "YOUR_REAL_ACCOUNT_ID"
```

عبارت `YOUR_REAL_ACCOUNT_ID` را با شناسهٔ واقعی جایگزین کنید. این خط باید بالای فایل و پیش از اولین بخشی باشد که با `[` شروع می‌شود؛ افزودن آن به انتهای فایل معنای دیگری در قالب TOML پیدا می‌کند. Account ID با Database ID فرق دارد.

نام ریپو `WIHM-Cloudflare` است و نام پیش‌فرض Worker در این فایل `cloudflare-messenger`. لازم نیست این دو یکسان باشند. اگر قبلاً در همین حساب برنامهٔ دیگری به نام `cloudflare-messenger` دارید، پیش از اولین انتشار نامی مانند `wihm-chat-ali` برای خط `name` انتخاب کنید. دستورهای انتشار و کلید، نام را از همین فایل می‌خوانند. نام و حروف انتخاب‌شده را برای ادامه ثابت نگه دارید تا برنامهٔ دیگری را ناخواسته به‌روز نکنید.

نام دیتابیس را برای دنبال‌کردن این راهنما `messenger-db` نگه دارید، چون دستورهای `db:init` داخل `package.json` از همین نام استفاده می‌کنند. اگر از قبل چنین دیتابیسی دارید، آن را حذف نکنید؛ بخش خطای «دیتابیس از قبل وجود دارد» را ببینید.

<a id="local"></a>
## ۸. آزمایش روی رایانه، اختیاری

این مرحله برای دیدن برنامه پیش از انتشار است. اگر فقط نسخهٔ آنلاین را می‌خواهید، مستقیم به مرحلهٔ ۹ بروید.

### ساخت کلید نسخهٔ محلی

داخل پوشهٔ پروژه اجرا کنید:

```bash
node -e "require('node:fs').writeFileSync('.dev.vars', 'JWT_SECRET=' + require('node:crypto').randomBytes(32).toString('hex') + '\n', {flag:'wx'})"
```

این دستور یک فایل مخفی به نام `.dev.vars` و یک کلید تصادفی می‌سازد؛ کلید را روی صفحه چاپ نمی‌کند. لازم نیست فایل را باز یا چیزی داخل آن بنویسید. اگر `EEXIST` دیدید، فایل از قبل موجود است؛ در صورت نصب قبلی، از همان فایل معتبر استفاده کنید و آن را بازنویسی نکنید.

فایل `.dev.vars.example` فقط نمونه است و مقدار خالی آن برای اجرای برنامه کافی نیست. فایل واقعی باید `.dev.vars` باشد، بدون پسوند `.txt`.

### ساخت جدول‌های محلی و اجرا

```bash
npm run db:init:local
npm run dev
```

وقتی ترمینال آدرس آماده‌شدن سرور را نشان داد، آن را در مرورگر باز کنید. آدرس معمول:

```text
http://localhost:8787
```

پنجرهٔ ترمینال را باز نگه دارید. برای توقف سرور روی آن کلیک کنید و `Ctrl + C` بزنید. اگر در ویندوز پرسید `Terminate batch job (Y/N)?`، حرف `Y` و Enter بزنید.

برای آزمایش دو کاربر، برنامه را در دو مرورگر متفاوت، یا یک پنجرهٔ عادی و یک پنجرهٔ ناشناس باز کنید. دو زبانهٔ عادی یک مرورگر فضای ورود مشترک دارند و برای این آزمایش مناسب نیستند. مراحل ساخت حساب در [بخش استفاده](#use) آمده است.

`localhost` یعنی همین دستگاه: بازکردن آن روی گوشی به رایانهٔ شما وصل نمی‌شود. برای استفادهٔ عادی روی گوشی، نسخهٔ آنلاین مرحلهٔ ۱۰ را راه‌اندازی کنید.

دیتابیس محلی داخل `.wrangler/state` نگهداری می‌شود و با دیتابیس آنلاین فرق دارد. حساب و پیام آزمایشی شما خودکار به نسخهٔ آنلاین منتقل نمی‌شوند. تغییر `database_id` بعد از آزمایش محلی هم ممکن است مسیر دادهٔ محلی مورد استفادهٔ Wrangler را عوض کند؛ به همین دلیل در این راهنما ابتدا شناسهٔ اصلی را تنظیم کردیم.

<a id="remote-schema"></a>
## ۹. ساخت جدول‌های دیتابیس آنلاین

اگر سرور محلی هنوز باز است، با `Ctrl + C` آن را متوقف کنید تا بتوانید دستور بعدی را بنویسید.

داخل پوشهٔ پروژه اجرا کنید:

```bash
npm run db:init:remote
```

اگر Wrangler دربارهٔ اجرای دستور روی دیتابیس آنلاین تأیید خواست، نام دیتابیس را بررسی کنید؛ باید `messenger-db` متعلق به همین پروژه باشد. سپس `Y` و Enter بزنید.

این دستور فایل `schema.sql` پروژه را روی D1 آنلاین اجرا می‌کند و جدول‌ها را می‌سازد. فایل فعلی از `CREATE TABLE IF NOT EXISTS` استفاده می‌کند و دستور پاک‌کردن جدول ندارد. موفق‌بودن این مرحله باید در ترمینال گزارش شود. اجرای `db:init:local` جای این مرحله را نمی‌گیرد.

برای بررسی وجود جدول‌ها:

```bash
npx wrangler d1 execute messenger-db --remote --command="SELECT name FROM sqlite_master WHERE type='table' AND name IN ('users','chats','chat_members','messages') ORDER BY name;"
```

باید هر چهار نام `chat_members`، `chats`، `messages` و `users` را در نتیجه ببینید. این دستور فقط نام جدول‌ها را می‌خواند.

<a id="deploy"></a>
## ۱۰. ساخت کلید امنیتی و انتشار پیام‌رسان

### ۱۰.۱. کلید مخصوص نسخهٔ آنلاین

داخل پوشهٔ پروژه اجرا کنید:

```bash
node -e "require('node:fs').writeFileSync('.env.production', 'JWT_SECRET=' + require('node:crypto').randomBytes(32).toString('hex') + '\n', {flag:'wx'})"
```

این دستور فایل `.env.production` را با یک کلید تصادفی مستقل از کلید محلی می‌سازد. اگر فایل از قبل وجود داشته باشد، آن را بازنویسی نمی‌کند. لازم نیست کلید را به‌صورت دستی انتخاب یا در ترمینال کپی کنید.

این فایل محرمانه است. از آن در محل خصوصی خود نسخهٔ پشتیبان نگه دارید. `.gitignore` پروژه مانع اضافه‌شدن معمول آن به Git می‌شود؛ بااین‌حال فایل را به‌صورت دستی در GitHub، پیام‌رسان یا اسکرین‌شات منتشر نکنید. مقدار کلید را داخل `wrangler.toml`، `public` یا کد برنامه ننویسید.

`JWT_SECRET` رمز ورود کاربران نیست و مقدار آن را نباید به کاربران بدهید. برنامه برای ورود و ثبت‌نام به کلیدی با حداقل ۳۲ بایت نیاز دارد؛ دستور بالا مقدار تصادفی ۶۴کاراکتری مناسب می‌سازد.

### ۱۰.۲. انتشار کد و کلید با یک دستور

```bash
npm run deploy -- --secrets-file .env.production
```

دو خط تیرهٔ جداگانهٔ `--` در وسط دستور لازم است تا npm گزینهٔ فایل کلید را به Wrangler بدهد. این روش کلید را همراه همان نسخهٔ برنامه در Cloudflare ثبت می‌کند؛ داشتن `.env.production` یا `.dev.vars` روی رایانه به‌تنهایی کلید را روی سرور تنظیم نمی‌کند. [انتشار هم‌زمان کد و Secret در مستندات Cloudflare](https://developers.cloudflare.com/workers/configuration/secrets/#upload-secrets-alongside-code)

اگر اولین بار است از Workers استفاده می‌کنید، ممکن است انتخاب حساب یا تنظیم زیر دامنهٔ `workers.dev` خواسته شود. حساب صحیح را انتخاب کنید. برای زیر دامنه یک نام انگلیسی موجود انتخاب کنید و مراحل اعلام‌شده را کامل کنید. این نام بخشی از آدرس نهایی شماست.

در پایان، ترمینال آدرسی با ساختار زیر چاپ می‌کند. این نمونه است و قابل استفاده به‌عنوان آدرس نصب شما نیست:

```text
https://cloudflare-messenger.YOUR-SUBDOMAIN.workers.dev
```

آدرس واقعی را از خروجی خودتان کپی کنید و جایی نگه دارید. اگر نام Worker را تغییر داده‌اید، ابتدای آدرس هم با همان نام ساخته می‌شود. آدرس `workers.dev` امکان شروع بدون دامنهٔ شخصی را فراهم می‌کند. [توضیح رسمی آدرس workers.dev](https://developers.cloudflare.com/workers/configuration/routing/workers-dev/)

### ۱۰.۳. بررسی نصب آنلاین

1. آدرس واقعی چاپ‌شده را در مرورگر باز کنید؛ باید صفحهٔ ورود پیام‌رسان را ببینید.
2. طبق مرحلهٔ ۱۱ یک حساب تازه بسازید. حساب آزمایشی `localhost` در این نسخه وجود ندارد، مگر جداگانه اینجا ساخته شده باشد.
3. آدرس را در مرورگر دوم یا گوشی باز کنید و حساب دوم بسازید.
4. از حساب اول، کاربر دوم را جستجو و یک پیام بفرستید؛ رسیدن آن را در دستگاه دوم بررسی کنید.
5. ترمینال رایانه را ببندید و سایت را دوباره روی گوشی باز کنید. نسخهٔ منتشرشده باید همچنان در دسترس باشد.

برای دیدن برنامه در داشبورد، وارد همان حساب Cloudflare شوید، بخش `Workers & Pages` را باز و Worker با نام انتخاب‌شده در `wrangler.toml` را انتخاب کنید. دیتابیس را در قسمت `D1 SQL Database` می‌بینید؛ در بعضی چیدمان‌ها زیر `Storage & Databases` قرار دارد.

اگر صفحهٔ ورود باز می‌شود اما ثبت‌نام خطای 503 می‌دهد، بخش خطای کلید امنیتی را ببینید. بازشدن ظاهر سایت به‌تنهایی تأیید کارکرد سرور نیست؛ ارسال واقعی پیام در دو حساب، بررسی نهایی شماست.

<a id="use"></a>
## ۱۱. ساخت حساب و ارسال پیام

### ساخت حساب

1. آدرس آنلاین پیام‌رسان را باز کنید.
2. زبانهٔ «ثبت‌نام» را انتخاب کنید.
3. در «نام نمایشی»، نامی مانند «علی احمدی» وارد کنید. نام فارسی پشتیبانی می‌شود و حداکثر طول آن ۱۰۰ کاراکتر است.
4. یک نام کاربری با ۳ تا ۲۰ کاراکتر انتخاب کنید؛ فقط حروف انگلیسی، عدد و زیرخط `_` پذیرفته می‌شود. مثال: `ali_2026`.
5. یک رمز عبور انتخاب کنید. برنامه حداقل ۶ کاراکتر می‌پذیرد؛ برای حساب واقعی از رمز طولانی و اختصاصی استفاده کنید و آن را در مدیر رمز یا محل امن نگه دارید.
6. «ایجاد حساب کاربری» را بزنید. پس از موفقیت وارد برنامه می‌شوید.

نام کاربری باید یکتا باشد. برای ورودهای بعدی، زبانهٔ «ورود» را بزنید و نام کاربری و همان رمز را وارد کنید. حساب پیام‌رسان از حساب GitHub و Cloudflare جداست. هیچ حساب مدیر یا رمز ورود آماده‌ای در پروژه وجود ندارد.

### گفتگوی خصوصی

1. مخاطب شما هم باید در همان نصب و همان آدرس پیام‌رسان حساب داشته باشد.
2. روی `+` در بالای فهرست گفتگوها بزنید.
3. نام کاربری مخاطب را جستجو کنید؛ کمی صبر کنید تا نتیجه ظاهر شود.
4. روی نتیجه یا «گفتگو» بزنید.
5. متن را بنویسید و دکمهٔ ارسال را بزنید. در رایانه Enter پیام را می‌فرستد و `Shift + Enter` خط جدید ایجاد می‌کند.

هر پیام حداکثر ۱۰٬۰۰۰ کاراکتر دارد. پیام‌های گفتگوی باز با وب‌سوکت می‌رسند؛ ظاهرشدن گفتگوی تازه یا پیش‌نمایش پیام گفتگوی دیگر ممکن است تا تازه‌سازی بعدی، حدود ۵ ثانیه در صفحهٔ فعال، طول بکشد.

### ساخت گروه و افزودن عضو

1. روی `+` و سپس «ساخت گروه» بزنید.
2. نام گروه را وارد کنید.
3. کاربران را جستجو و حداقل یک نفر را انتخاب کنید. برای یافتن شخص بعدی، عبارت جستجو را عوض کنید؛ انتخاب‌های قبلی حفظ می‌شوند.
4. دکمهٔ «ساخت گروه» را بزنید.
5. برای افزودن افراد دیگر، گروه را باز کنید و «افزودن عضو» را در سربرگ بزنید؛ کاربر را پیدا و انتخاب کنید و «افزودن اعضا» را بزنید.

در این نسخه هر عضو فعلی گروه می‌تواند عضو جدید اضافه کند. نقش مدیر، حذف عضو و لینک دعوت گروه پیاده‌سازی نشده‌اند.

### پیام‌های قبلی و قطع اینترنت

وقتی پیام قدیمی‌تری روی سرور وجود داشته باشد و هنوز دریافت نشده باشد، دکمهٔ «پیام‌های قبلی» بالای بخش پیام‌ها ظاهر می‌شود. با زدن آن، صفحهٔ قبلی دریافت می‌شود.

هنگام قطع ارتباط، برنامه دوباره برای اتصال تلاش می‌کند و پس از وصل‌شدن، تاریخچه را تازه می‌کند. متن واردشده هنگام تلاش برای ارسال در حالت قطع اتصال حفظ می‌شود. بعد از برگشت اتصال، خودتان ارسال را دوباره بزنید؛ صف ارسال آفلاین وجود ندارد.

## ۱۲. نصب روی گوشی و رایانه

پس از راه‌اندازی سرور، هر کاربر فقط به آدرس آنلاین برنامه نیاز دارد. این نصب از طریق مرورگر انجام می‌شود و فایل APK یا IPA ندارد.

### Android

1. آدرس آنلاین را در Chrome باز کنید؛ از مرورگر داخلی تلگرام یا برنامه‌های دیگر خارج شوید.
2. اگر بنر «نصب اپلیکیشن پیام‌رسان» ظاهر شد، «نصب» را بزنید.
3. اگر بنر نبود، منوی سه‌نقطهٔ Chrome را باز کنید و گزینهٔ `Install app` یا `Add to Home screen` را پیدا کنید.
4. تأیید کنید و از آیکون ایجادشده برنامه را باز کنید.

### iPhone و iPad

1. آدرس آنلاین را در Safari باز کنید.
2. دکمهٔ اشتراک‌گذاری، یعنی مربع با فلش رو به بالا، را بزنید. در چیدمان‌هایی که این دکمه پنهان است، ابتدا منوی بیشتر را باز کنید.
3. `Add to Home Screen` را انتخاب کنید. اگر نبود، در فهرست کارها پایین بروید و از `Edit Actions` آن را پیدا کنید.
4. اگر گزینهٔ `Open as Web App` نمایش داده شد، آن را روشن نگه دارید و `Add` را بزنید.
5. آیکون را از صفحهٔ اصلی باز کنید. [راهنمای رسمی Apple](https://support.apple.com/guide/iphone/open-as-web-app-iphea86e5236/ios)

### رایانه

در Chrome یا Edge، آدرس آنلاین را باز و از آیکون نصب کنار نوار آدرس استفاده کنید. در Chrome می‌توانید منوی سه‌نقطه، `Cast, save, and share` و سپس `Install page as app` را هم بررسی کنید. [راهنمای رسمی Chrome](https://support.google.com/chrome/answer/9658361?co=GENIE.Platform%3DDesktop&hl=en)

نمایش گزینهٔ نصب به مرورگر و دستگاه بستگی دارد. اگر آن را نمی‌بینید، پیام‌رسان را از همان صفحهٔ مرورگر استفاده کنید. آدرس آنلاین باید با `https://` باز شود. ممکن است نسخهٔ نصب‌شده برای اولین بار دوباره نام کاربری و رمز بخواهد.

<a id="domain"></a>
## ۱۳. اتصال دامنهٔ شخصی، اختیاری

اگر آدرس `workers.dev` برایتان کافی است، این مرحله را رد کنید.

برای دامنهٔ شخصی باید مالک یک دامنه باشید و آن دامنه در همان حساب Cloudflare به‌صورت فعال ثبت شده باشد. بعد:

1. در داشبورد Cloudflare وارد `Workers & Pages` شوید.
2. Worker همین پیام‌رسان را باز کنید.
3. مسیر `Settings > Domains & Routes > Add > Custom Domain` را بروید.
4. یک زیردامنهٔ استفاده‌نشده، مانند `chat.example.com` از دامنهٔ خودتان، وارد کنید. `example.com` فقط نمونه است.
5. افزودن را تأیید کنید و تا فعال‌شدن DNS و گواهی صبر کنید.
6. آدرس را با `https://` باز و ورود و ارسال پیام را آزمایش کنید.

Cloudflare رکورد و گواهی لازم را برای Custom Domain ایجاد می‌کند. اگر برای آن نام از قبل CNAME وجود داشته باشد، ابتدا باید تداخل را بررسی کنید؛ برای نصب پیام‌رسان، رکورد سایت دیگری را بدون بررسی حذف نکنید. [شرایط و مراحل رسمی Custom Domain](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/)

با تغییر آدرس از `workers.dev` به دامنهٔ شخصی، ممکن است نیاز باشد دوباره وارد حساب پیام‌رسان شوید؛ وضعیت ورود مرورگر به آدرس سایت وابسته است. اگر همچنان به همان Worker و دیتابیس وصل باشید، این کار حساب جدیدی روی سرور نمی‌سازد.

<a id="maintenance"></a>
## ۱۴. روشن‌کردن دوباره، به‌روزرسانی و نگهداری

### آیا باید هر بار دستور اجرا کنم؟

برای نسخهٔ آنلاین خیر؛ Cloudflare آن را اجرا می‌کند. برای دیدن دوبارهٔ نسخهٔ محلی، وارد پوشهٔ پروژه شوید و `npm run dev` را اجرا کنید. دستور ساخت دیتابیس، ساخت کلید و انتشار، کار روزانهٔ کاربران نیست.

### به‌روزرسانی در روش Git

ابتدا از `wrangler.toml`، `.env.production` و در صورت استفادهٔ محلی `.dev.vars`، بیرون از پوشهٔ پروژه و در محل خصوصی نسخهٔ پشتیبان بگیرید. کلیدها را در ریپوی خود هم منتشر نکنید.

داخل پوشهٔ پروژه اجرا کنید:

```bash
git pull --ff-only
npm ci
npm run typecheck
npm test
```

هر خط را تنها بعد از موفقیت قبلی اجرا کنید. تغییر محلی Database ID در `wrangler.toml` ممکن است با تغییر همان فایل در نسخهٔ تازه تداخل پیدا کند. اگر Git گفت تغییرات محلی بازنویسی می‌شوند، ادامه ندهید و از `reset --hard` یا پاک‌کردن پوشه استفاده نکنید. روش دریافت نسخهٔ تازه در پوشهٔ جدا، در بند بعد برای این حالت هم قابل استفاده است.

پس از خواندن توضیحات نسخهٔ جدید، بررسی تنظیمات حساب و دیتابیس و موفقیت تست‌ها، با همان کلید قبلی منتشر کنید:

```bash
npm run deploy -- --secrets-file .env.production
```

در به‌روزرسانی معمول، دیتابیس تازه نسازید و کلید JWT را دوباره تولید نکنید. تغییر نام Worker، شناسهٔ دیتابیس یا تنظیمات Durable Objects می‌تواند برنامه را به محل دادهٔ دیگری وصل کند. دستورهای مهاجرت دیتابیس را فقط مطابق راهنمای همان نسخه اجرا کنید؛ `schema.sql` همیشه جای مهاجرت نسخه‌های آینده را نمی‌گیرد.

### نسخهٔ تازه در پوشهٔ جدا یا روش ZIP

1. پوشهٔ فعلی را نگه دارید و نسخهٔ تازه را در یک پوشهٔ جدا دریافت کنید.
2. در `wrangler.toml` نسخهٔ تازه، فقط نام Worker، Database ID و در صورت استفاده Account ID قبلی خود را وارد کنید؛ برای این کار از تنظیمات پشتیبان بخوانید. فایل تنظیمات قدیمی را کامل روی فایل تازه ننویسید، چون ممکن است تنظیم یا مهاجرت جدیدی اضافه شده باشد.
3. فایل محرمانهٔ `.env.production` قبلی را به پوشهٔ تازه کپی کنید. برای آزمایش محلی، `.dev.vars` را هم منتقل کنید.
4. داخل پوشهٔ تازه `npm ci`، سپس بررسی‌ها و دستور انتشار بالا را اجرا کنید.
5. برنامهٔ آنلاین را با همان حساب قبلی بررسی کنید. تا مطمئن نشده‌اید نصب درست است، پوشهٔ قدیمی را پاک نکنید.

### اگر فایل کلید گم شد

تا وقتی Secret روی Cloudflare باقی است، گم‌شدن فایل رایانه به‌تنهایی برنامهٔ آنلاین را متوقف نمی‌کند. برای انتشار فقط کد می‌توانید `npm run deploy` اجرا کنید؛ Secretهای موجود در انتشار معمول حفظ می‌شوند. مقدار Secret ذخیره‌شده از داشبورد یا `secret list` قابل بازیابی نیست.

برای تعویض عمدی کلید، ابتدا فایل قبلی را در محل خصوصی نگه دارید و نام آن را در پوشهٔ پروژه به `.env.production.saved-01` تغییر دهید؛ اگر این نام هم موجود است، نام دیگری انتخاب کنید. سپس دستور تولید کلید مرحلهٔ ۱۰.۱ و دستور انتشار مرحلهٔ ۱۰.۲ را اجرا کنید. تغییر کلید، توکن‌های ورود قبلی را نامعتبر می‌کند و کاربران باید دوباره وارد شوند؛ رمز حساب و خود حساب کاربر با این تغییر عوض نمی‌شود. [مدیریت Secretها](https://developers.cloudflare.com/workers/configuration/secrets/)

### نسخهٔ پشتیبان دیتابیس

برای گرفتن خروجی D1 در Windows، یک پوشهٔ خصوصی بیرون از پروژه بسازید و سپس:

```bat
mkdir "%USERPROFILE%\WIHM-backups"
npx wrangler d1 export messenger-db --remote --output="%USERPROFILE%\WIHM-backups\messenger-backup-01.sql"
```

اگر پوشه از قبل وجود داشت، پیام آن مانع اجرای خط بعد نیست. برای هر پشتیبان، نام فایل تازه‌ای مانند `messenger-backup-02.sql` انتخاب کنید تا خروجی قبلی را بازنویسی نکنید.

در macOS یا Ubuntu:

```bash
mkdir -p "$HOME/WIHM-backups"
npx wrangler d1 export messenger-db --remote --output="$HOME/WIHM-backups/messenger-backup-01.sql"
```

این خروجی شامل داده‌های حساس مانند پیام‌ها و هش رمزهاست؛ آن را عمومی نکنید. این دستور فقط D1 را صادر می‌کند و خروجی SQLite داخلی Durable Objects یا کلید JWT را شامل نمی‌شود. آن را پشتیبان کامل همهٔ اجزای نصب در نظر نگیرید. فایل SQL را برای آزمایش، مستقیم روی دیتابیس زنده وارد نکنید. [مستندات خروجی D1](https://developers.cloudflare.com/d1/best-practices/import-export-data/)

<a id="troubleshooting"></a>
## ۱۵. رفع خطاهای رایج

متن خطا را از همان ترمینال بخوانید و ابتدا مطمئن شوید در پوشه‌ای هستید که `package.json` و `wrangler.toml` داخل آن قرار دارند.

### `node`، `npm` یا `git` پیدا نمی‌شود

اگر `not recognized` یا `command not found` دیدید، پنجره را ببندید و دوباره باز کنید و دستور نسخه را امتحان کنید. اگر همچنان پیدا نشد، نصب مرحلهٔ ۳ را کامل کنید. در ویندوز، گزینهٔ افزودن ابزار به PATH باید فعال باشد. در Ubuntu، نصب nvm و بارگذاری `~/.bashrc` را بررسی کنید.

### خطای `npm.ps1 cannot be loaded` در PowerShell

Command Prompt را طبق مرحلهٔ ۲ باز و دستور را آنجا اجرا کنید. برای نصب این پروژه نیازی به تغییر دائمی Execution Policy ویندوز ندارید. اگر در PowerShell می‌مانید، `npm.cmd` و `npx.cmd` را به‌جای `npm` و `npx` اجرا کنید؛ دستورهای مسیرِ این راهنما همچنان برای cmd نوشته شده‌اند.

### خطای `ENOENT` یا پیدا نشدن `package.json`

در پوشهٔ درست نیستید یا ZIP را کامل استخراج نکرده‌اید. `dir` یا `ls` را اجرا کنید و پوشه‌ای را پیدا کنید که خود فایل `package.json` در آن است. اجرای دستور از پوشهٔ `public` یا `src` درست نیست.

### دانلود npm قطع می‌شود یا `ETIMEDOUT` می‌بینم

اتصال اینترنت و دسترسی به npm و GitHub را بررسی کنید و سپس `npm ci` را دوباره اجرا کنید. اگر خطای گواهی دارید، تاریخ دستگاه و تنظیمات شبکه یا پراکسی را بررسی کنید؛ اعتبارسنجی TLS را غیرفعال نکنید. خطای ناهماهنگی `package.json` و `package-lock.json` با تغییر شبکه رفع نمی‌شود؛ در آن حالت هر دو فایل را از یک نسخهٔ پروژه دریافت کنید.

### خطای دسترسی به فایل، `EPERM` یا `EACCES`

نسخه‌های باز سرور محلی را ببندید و دوباره امتحان کنید. پروژه را در پوشهٔ شخصی خود نگه دارید، نه پوشهٔ محافظت‌شده‌ای مانند `Program Files`. در لینوکس، `npm ci` را با `sudo` اجرا نکنید. اگر متن خطا دربارهٔ سیستم‌عامل یا اجرای `workerd` است، شرایط پشتیبانی مرحلهٔ ۱ را دوباره بررسی کنید.

### خطای ورود Cloudflare، `Authentication error` یا حساب اشتباه

ابتدا `npx wrangler whoami` اجرا کنید. برای تغییر ورود، `npx wrangler logout` و سپس `npx wrangler login` را اجرا کنید. گیرکردن برگشت مرورگر روی localhost را با `npx wrangler login --device` رفع کنید. اگر عضو حساب دیگری هستید، ممکن است اجازهٔ ساخت Worker یا D1 نداشته باشید؛ از حساب خودتان یا حسابی با دسترسی لازم استفاده کنید. Account ID در تنظیمات باید متعلق به همان حسابی باشد که دیتابیس را در آن ساختید.

### دیتابیس `messenger-db` از قبل وجود دارد

دستور زیر دیتابیس‌های حساب را فهرست می‌کند:

```bash
npx wrangler d1 list
```

اگر دیتابیس متعلق به همین نصب قبلی است، UUID آن را در `database_id` بگذارید و از همان استفاده کنید. اگر مربوط به برنامهٔ دیگری است، آن را حذف یا مقداردهی نکنید. برای نصب مستقل، نام تازه‌ای انتخاب کنید و علاوه بر `database_name` در `wrangler.toml`، نام دیتابیس در هر دو اسکریپت `db:init:local` و `db:init:remote` فایل `package.json` را هم هماهنگ تغییر دهید. سپس دستور ساخت D1 را با نام تازه اجرا کنید.

### خطای `database_id`، UUID یا پیدا نشدن دیتابیس

در `wrangler.toml` نباید عبارت `local-messenger-db`، `YOUR_DATABASE_ID` یا نمونهٔ `xxxxxxxx...` باقی مانده باشد. UUID واقعی D1 را وارد کنید؛ Account ID را جای آن نگذارید. فایل را ذخیره و حساب انتخاب‌شده در `whoami` را بررسی کنید. اگر دو بخش D1 برای binding یکسان اضافه شده، تنها بخش صحیح را نگه دارید.

### خطای `no such table: users` یا جدول دیگری

اگر مشکل روی سایت آنلاین است، `npm run db:init:remote` و دستور بررسی جدول‌ها در مرحلهٔ ۹ را برای دیتابیس صحیح اجرا کنید. اگر مشکل روی localhost است، `npm run db:init:local` را اجرا کنید. سپس صفحه را تازه کنید. ساخت جدول در محیط محلی، محیط آنلاین را آماده نمی‌کند.

### صفحه باز می‌شود ولی ورود یا ثبت‌نام خطای 503 می‌دهد

این پروژه وقتی کلید JWT تنظیم نشده یا کوتاه است، ورود و ثبت‌نام را متوقف می‌کند.

- در نسخهٔ محلی، وجود فایل واقعی `.dev.vars` با مقدار غیرخالی `JWT_SECRET` را بررسی کنید و سرور `npm run dev` را متوقف و دوباره اجرا کنید.
- در نسخهٔ آنلاین، از همان پوشهٔ دارای تنظیمات صحیح، دستور `npm run deploy -- --secrets-file .env.production` را اجرا کنید. فایل نمونهٔ خالی کافی نیست.
- برای دیدن نام Secretهای Worker فعلی، `npx wrangler secret list` را اجرا کنید. باید نام `JWT_SECRET` در فهرست باشد؛ این دستور خود کلید را نشان نمی‌دهد.

اگر کلید فقط در `.dev.vars` وجود دارد، نسخهٔ آنلاین هنوز آن را ندارد. برای رفع خطا کلید کوتاه یا پیش‌فرض عمومی در کد نگذارید.

### خطای `EEXIST` هنگام ساخت کلید

دستور تولید کلید عمداً فایل موجود را بازنویسی نمی‌کند. اگر قبلاً آن را ساخته‌اید و مقدار معتبر دارد، همان را نگه دارید و مرحلهٔ بعد را انجام دهید.

اگر فقط نمونهٔ خالی `JWT_SECRET=""` را کپی کرده‌اید، ابتدا مطمئن شوید کلید معتبر یا نصب فعالی به آن وابسته نیست. در ویندوز از File Explorer و در مک یا لینوکس از فایل‌منیجر، نام فایل خالی را به `.dev.vars.saved-01` یا `.env.production.saved-01` تغییر دهید؛ اسم متناسب با همان فایل را انتخاب کنید. اگر فایل‌های نقطه‌دار پنهان‌اند، در ویندوز `View > Show > Hidden items`، در Finder دکمه‌های `Command + Shift + .` و در فایل‌منیجر Ubuntu دکمه‌های `Ctrl + H` را بزنید. سپس دستور تولید کلید مربوط به آن فایل را دوباره اجرا کنید. فایل پشتیبان را هم خصوصی نگه دارید. برای تغییر عمدی کلید معتبر، اثر خروج کاربران از حساب را در بخش نگهداری بخوانید.

### خطای `Unknown argument: secrets-file`

باید در پوشهٔ پروژه باشید و `npm ci` را با فایل‌های همین نسخه اجرا کرده باشید. `npx wrangler --version` را بررسی کنید. از دستور دقیق `npm run deploy -- --secrets-file .env.production` استفاده کنید؛ دستورهای مربوط به Pages یا Wrangler سراسری قدیمی با این مسیر یکسان نیستند.

### خطای مربوط به Durable Objects، SQLite یا migration

بررسی کنید این خطوط از `wrangler.toml` حذف یا تغییر نکرده باشند:

```toml
[[migrations]]
tag = "v1"
new_sqlite_classes = ["ChatRoom"]
```

برای نصب تازهٔ همین پروژه، از فایل تنظیمات همین نسخه استفاده کنید. پروژه از Durable Objects با SQLite استفاده می‌کند. تغییر آن به `new_classes` یا تغییر نام کلاس راه‌حل خطا نیست. در نصب موجود، تاریخچهٔ migration را خودسرانه بازنویسی نکنید؛ متن خطا و تنظیمات نسخهٔ قبلی را نگه دارید.

### آدرس برنامه ندارم یا `workers.dev` باز نمی‌شود

برای پیدا‌کردن آدرس، داشبورد `Workers & Pages`، Worker خودتان و `Settings > Domains & Routes` را بررسی کنید. آدرس نمونهٔ این راهنما را باز نکنید. اگر مسیر workers.dev غیرفعال است، همان‌جا آن را فعال کنید؛ اگر تنظیم `workers_dev = false` را قبلاً به فایل اضافه کرده‌اید، آن تنظیم هم باید با تصمیم شما هماهنگ شود.

اگر همان آدرس واقعی روی اینترنت دیگری باز می‌شود، مشکل می‌تواند از دسترسی شبکه یا DNS باشد؛ نصب صحیح برنامه تضمین نمی‌کند همهٔ شبکه‌ها به دامنهٔ Cloudflare دسترسی داشته باشند. آدرس را با `https://` آزمایش کنید.

### پورت 8787 اشغال است

سرور محلی قبلی را ببندید یا اجرا کنید:

```bash
npm run dev -- --port 8788
```

سپس آدرس اعلام‌شده، معمولاً `http://localhost:8788`، را باز کنید.

### کاربر یا پیام آزمایشی من در نسخهٔ آنلاین نیست

حساب‌های localhost و سایت آنلاین جدا هستند. در هر دستگاه آدرس را بررسی کنید؛ دو نصب متفاوت با دو دیتابیس کاربران مشترک ندارند. اگر همین نصب آنلاین قبلاً داده داشته، مطمئن شوید Database ID یا نام Worker را عوض نکرده‌اید. برای پیدا‌کردن اطلاعات قبلی، دیتابیس تازه نسازید.

### مخاطب در جستجو پیدا نمی‌شود

مخاطب باید قبلاً در همین نصب ثبت‌نام کرده باشد. نام کاربری را با حروف انگلیسی بررسی کنید. حساب خودتان در نتایج جستجوی مخاطبان نشان داده نمی‌شود. برای آزمایش حساب دوم از مرورگر یا پنجرهٔ ناشناس جدا استفاده کنید.

### پیام ارسال نمی‌شود یا وضعیت روی اتصال مجدد مانده است

اتصال اینترنت را بررسی و صفحه را تازه کنید. اگر پیام احراز هویت یا 401 دیدید، از حساب خارج شوید و دوباره وارد شوید؛ توکن‌های این نسخه پس از ۷ روز منقضی می‌شوند. برای ورود مجدد، تغییر JWT یا ساخت حساب تازه لازم نیست. در گروه باید عضو همان گروه باشید. بازکردن مستقیم آدرس `/ws` در نوار مرورگر روش استفاده از پیام‌رسان نیست و می‌تواند خطای نیاز به WebSocket بدهد.

### ظاهر قدیمی برنامه دیده می‌شود

نسخهٔ نصب‌شده و همهٔ زبانه‌های همان سایت را ببندید و سایت را دوباره باز کنید. در رایانه `Ctrl + Shift + R` را هم امتحان کنید. اگر لازم شد از تنظیمات مرورگر داده‌های محلی همان سایت را پاک کنید؛ این کار ورود ذخیره‌شده را پاک می‌کند و باید دوباره وارد شوید، اما دیتابیس آنلاین را حذف نمی‌کند.

### خطای عبور از سهمیه یا محدودیت مصرف

مصرف Worker، D1 و Durable Objects را در داشبورد همان حساب بررسی کنید. تعداد صفحه‌های باز و تازه‌سازی دوره‌ای فهرست گفتگوها بر مصرف اثر می‌گذارد. نوع محدودیت و زمان بازنشانی را از مستندات پلن خود بررسی کنید. پاک‌کردن دیتابیس یا ساخت دوبارهٔ کلید راه‌حل سهمیه نیست.
