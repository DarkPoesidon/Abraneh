# Ponytail audit — 1.5.0

What this repo does: WIHM is a personal messenger hosted on Cloudflare Workers, D1 and SQLite Durable Objects. This release adds automatic server federation, experimental two-device MLS chats, account security, portable backups, channels and direct calls. This review assumes small personal deployments, about ten active users and at most 200 backed-up chat rooms.

The review traced authentication and revocation, federation signatures and device trust, snapshot and restore boundaries, installer ownership checks, push delivery, update packaging, channel permissions and call consent. It used the regression tests, two independent local databases, desktop/mobile Chrome and the actual installer build. This is a code quality audit, not an independent cryptographic assessment.

## Should fix

1. **A forcibly terminated operation can prevent a later backup** (`src/maintenance.ts`, `src/backup.ts`).
   - **What this is:** A backup waits for registered requests to finish before reading a consistent snapshot.
   - **Problem:** If the runtime kills an invocation before its `finally` runs, its operation row remains. A later export refuses to proceed, even after the original invocation is gone. The failure is reproducible by leaving a row in `service_operations`.
   - **Fix:** Add a fencing mechanism before reclaiming abandoned operations. Expiring rows alone is unsafe because a slow invocation could still write. Until then, operator investigation is required after a hard runtime termination.
   - **If we skip it:** Backup creation can fail conservatively. It does not silently export an inconsistent archive or delete live data; the temporary write pause expires.

## Fixed during integration

- Replaced discovery-only results and required administrator pairing with ordinary chat search, automatic HTTPS server identity pins and signed delivery. Device fingerprint confirmation remains separate.
- Kept a stable account identity across aliases and independently verified the canonical address before using it.
- Blocked remote device lookup when the account has not allowed discovery. No caller cookies or login tokens go to peer servers.
- Made remote delivery immediate, with a persistent idempotent retry queue. Added generic encrypted-message push and retry isolation between recipients.
- Corrected stale history rendering during background sync and preserved the typed draft and caret.
- Fixed the closed native call dialog showing underneath the app and stopped local capture when the chat connection closes.
- Replaced oversized restore verification SQL with bounded batches; verified a real D1/room round trip through the installer helper.
- Kept strict target ownership and ChatRoom binding validation. Restore revokes sessions and old secure devices and disables public networking until reviewed.
- Added the public-fetch compatibility flag to normal installation, updater installation and signed update deployment.

## Accepted limits

MLS is explicitly experimental and uses a library without an independent security audit. Secure threads are for two verified devices, not transparent multi-device or group encryption. Old chats and channels remain server-readable. HTTPS identity pinning trusts the first successful HTTPS contact; manual pinning is optional and a changed server key fails closed.

Backup limits are 32 MiB, 200 rooms and a matching installer version. Direct calls have no TURN relay, group calling or cross-server signaling. Native audio was checked using synthetic microphones and local ICE; hardware camera quality and carrier networks were not verified. A custom-domain API mapping does not prove a live DNS record and issued TLS certificate.

Verdict: The reported federation architecture problem is fixed in the tested two-server flow. Keep the MLS experimental label and the conservative backup limits.

Not checked: deployment into the user's two real Cloudflare accounts, physical passkeys/cameras, real mobile carrier media paths, full account quota accounting, and independent MLS security assessment. Installer tests cover Termux bootstrap; the new release still needs a fresh real-device Termux run.
